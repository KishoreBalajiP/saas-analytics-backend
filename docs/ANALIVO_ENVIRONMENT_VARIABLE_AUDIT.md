# Analivo environment-variable audit

Audit date: 2026-10-23. Authority: `src/config/env.js`, its production guards, job registration, service call sites, `.env.example`, CI workflows, and the isolated test runner. No secret values were read into this document. The local `.env` and deployment settings were not changed.

## Launch conclusions

Production must provide real values for `MONGODB_URI`, `JWT_SECRET`, `ENCRYPTION_KEY`, `CORS_ORIGINS`, `CLIENT_URL`, `SOCKET_CORS_ORIGIN`, `REDIS_URL`, S3 settings when storage is S3, SMTP settings when email is enabled, and `METRICS_TOKEN` when metrics are exposed. `AUDIT_CHAIN_KEY` and `METRICS_TOKEN` previously shared with this project are treated as exposed and must be rotated; their old values are intentionally not reproduced.

AI is safely disabled with `AI_PROVIDER=noop` and an empty key. If enabled, use `AI_PROVIDER=gemini`, a supported stable model such as `gemini-2.5-flash`, and a server-side Google AI API key in `AI_API_KEY`. Anthropic/Claude is not supported by the current implementation.

The following scheduled jobs are enabled by the example configuration: billing lifecycle, invitation expiry, security detection, email outbox, cleanup, sheet sync, stale recovery, and tenant-export expiry. Tenant purge and billing reconciliation remain disabled by default. Do not enable destructive or externally visible jobs until their production data-retention, lease, alerting, and rollback checks are approved.

## Classification rules

`REQUIRED` means production startup or a core launch path needs a valid value. `CONDITIONALLY_REQUIRED` means the value is needed only when its feature/provider/job is enabled. `OPTIONAL` means the implementation has a safe default or explicitly supports empty. `UNUSED_OR_OBSOLETE` means it is present in the example but not consumed by the current loader/call sites. `IMPLEMENTATION_GAP` means documentation or intent exists without a complete implementation.

## Validation and unresolved issues

- `npm run ci:guards` passes after the Gemini change.
- The example is documentation, not production configuration; no real endpoint, credential, price, SMTP sender, S3 bucket, Google key, or deployment secret was invented.
- The current repository does not provide authenticated access to the complete GitHub Actions logs, so the backend run's exact remote failing test remains externally unresolved; local reproduction is recorded in the final report.
- `AUDIT_CHAIN_KEY` rotation must preserve the old key in `AUDIT_CHAIN_PREVIOUS_KEYS` during the verification window, then remove it only after historical records are reverified.

## Release verification evidence

- Frontend: typecheck, lint, production build, whitespace check, and the full 131-file/757-test suite passed locally.
- Backend: all five CI guards, adapter syntax validation, focused AI integration (5/5), and Gemini adapter unit tests (4/4) passed.
- Backend full suite: 1,559 tests ran under the process-scoped `MONGOMS_VERSION=6.0.14` test override; 1,520 passed and 39 failed. This remains a release blocker and is not evidence to change production MongoDB settings.
- The locally cached MongoDB 8.2.6 archive failed its checksum validation. The archive was not used, checksum validation was not disabled, and no production configuration was altered.
- The public GitHub workflow pages expose failed status and frontend annotations but not complete authenticated logs. No workflow rerun, deployment, commit, or push was performed.
